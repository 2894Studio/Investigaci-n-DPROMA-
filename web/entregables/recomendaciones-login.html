Recomendaciones Login

UX / Arquitectura de la información

  • Recuerda el email/usuario en el siguiente intento tras un error (nunca borrar el campo entero).
  • Si hay MFA, indica claramente qué método se usará antes de pedirlo (app authenticator, SMS, email) y ofrece un método de respaldo.
  • No bloquear el pegado de contraseñas (rompe gestores de contraseñas).
  • No re-pidas datos ya introducidos en el mismo flujo.
  • Mensajes de error específicos y accionables, por ejemplo: "La contraseña debe tener al menos 8 caracteres", no sirven mensajes tipo "Dato inválido" que no dan ninguna información del problema real.
  • Por seguridad, en error de credenciales usa un mensaje neutro ("Usuario o contraseña incorrectos") sin indicar cuál de los dos falló, pero sigue siendo claro y no genérico.
  • Indica intentos restantes antes de un bloqueo de cuenta, y qué hacer si se bloquea (contactar a TI, link directo).
  • Feedback de carga visible en el botón de iniciar sesión o login (spinner + texto "Verificando…") para evitar doble click y dar certeza de que algo está pasando.
  • Usa placeholder para indicar el tipo de dato que debe introducirse en cada campo.
  • Enlace de "¿Olvidaste tu contraseña?" siempre visible, no solo tras un error.
Recomendaciones Login

UI / Visual y estados

  • Contraste de texto ≥4.5:1 (normal) y ≥3:1 (texto grande) — revisa especialmente el placeholder y los mensajes de ayuda, que suelen quedar en gris claro insuficiente.
  • Define visualmente los estados de cada campo / botón (Default, hover, focus, active, disabled).
  • Usar toggle de "mostrar contraseña" (icono de ojo), mejora usabilidad y reduce errores de tecleo, especialmente en desktop donde no hay autocorrección del móvil.
  • En desktop aprovecha el espacio usando el formulario centrado, evitando que quede perdido en pantallas grandes.
  • No uses solo color para indicar error, un error común es usar solo borde rojo sin icono ni texto.

Accesibilidad

  • Orden de tabulación lógico: usuario → contraseña → mostrar/ocultar → "recordarme" → submit → "olvidé mi contraseña".
  • Tamaño mínimo de objetivo interactivo: 24×24px CSS, recomendado 44×44px para checkboxes y toggles (2.5.8), aunque sea desktop conviene por trackpads/precisión.
